# Session accounts 本地验收与回退

此清单用于本地测试包，不是线上真实账号测试已完成的声明。安装/更新/回退均需完整退出并重启 DSH；不要热移除隔离策略。先停止正在执行的会话，再用插件管理器安装本地 tgz。

## 最小验收

1. 确认 DSH 0.2.2-rc.1 / Cordis 4.1.x。打开账号设置，现有槽位和自定义模型目录应保留。
2. 登录两个账号 A、B；可包含不同 ghe.com 域名的同名用户。不复制、导出或截图任何 token/凭据文件。
3. 新建两个普通原生会话，选择 Copilot 模型，分别绑定 A、B。确认徽标身份和额度跟随各自绑定，而非全局默认。
4. 在两个会话发起简短请求并检查各自结果；另一个会话的选择不应变化。全局默认的模型、推理档位不应因固定绑定的选择而被覆盖。
5. 在会话空闲时 A→B→A，继续正常文本与工具对话；新请求使用新选择，历史与已完成工具结果仍在。不要为了测试自动执行有副作用的工具。
6. 将全局默认改成 B：固定 A 会话仍是 A；跟随默认的会话使用 B。切回「跟随全局默认」后再继续，不能复用不明账号签名。
7. 若切号后的模型请求最终失败：应出现简短提示，保留原始 DSH 错误供检查；弹窗不自动重跑模型、整轮或工具。关闭后同一通知不应重复打开。
8. 重启后查看原会话：绑定仍在。普通分支按所选历史前缀继承；新原生 fork 子代理按创建请求已捕获的账号继续，父会话后续修改不应重绑已有子代理。
9. 移除 A 后，绑定 A 的会话应明确不可用，不自动换 B；绑定 B 仍正常。重新授权 A 后按明确操作恢复。
10. 如使用远程 Host，在两个 Host 使用相同会话/账号 id 的测试场景中，旧 Host 的迟到数据/头像/错误不得更新当前 Host。每个 Host 都需安装对应功能。

## 压缩及定制配置

- 长上下文切号时，默认自动压缩应使用当前已捕获的请求账号，不应因旧账号额度不足阻止新账号继续。
- 显式设置的摘要 provider/model 覆盖仍有优先权；不能将该用户意图静默改成当前账号。
- 精确 provider/model 压缩策略继承受管理的 Copilot 路由；若新增账号在当前策略下需要重启，应明确提示，而不是忽略预算。
- 显式 API-key/认证/非原生端点覆盖属于无法确认账号身份的路径；插件不能假称它对应某个 OAuth 槽位或展示错误额度。

## 回退

完整退出 DSH 后，使用保留的头像修复测试包或之前版本替换本测试包，再启动。原账号记录和会话文件不应被删除。

旧版本不认识新版本的固定账号/受管理默认路由。回退后，这些会话可能显示模型不可用；可以重新安装本功能恢复绑定，或由用户显式选择旧版原生 Copilot 模型使用全局默认。不会在后台自动把固定绑定转换成其他账号。

## 安全反馈

反馈界面现象、操作顺序、DSH/插件版本、错误类别即可。不要提交凭据库、原始 token、Authorization 头或带签名参数的头像 URL。优先使用合成会话复现，真实模型请求可能产生费用。
